## Notes

- **DL-01**: The omission is exact and static: the novelty seam has no counter and the caller adds none, so a novelty-only consolidation run bills zero query-embedding units. The run-scoped benchmark accounting (instrumentOperationProvider) is a separate mechanism and unaffected.
- **DL-02**: Fault window confirmed line-for-line: bulk write commits at `mongodb-kb.ts:310-313`, parent update at `:320-322`, counter at `:375-377` after the helper returns. The audit's caveat stands: the transactional re-ingest path counts post-commit and is not affected by this hole.
- **DL-03**: All three indistinguishable cases (no calls / unknown usage / lost writes / unavailable aggregation) persist. The "degrades to call counts" comment at `mongodb-llm-enrichment.ts:53-56` remains false for the production ledger — there is no call-count path in `mongodb-cost-ledger.ts`.
- **DL-04**: This finding is a measurement-interpretation limitation by its own framing, and its "name these counters as indexing-operation estimates" remedy was applied in the module header and cost-model doc — hence PARTIAL rather than OPEN. The hard half of the remedy (separating embedding readiness/completion and provider token reconciliation from mutation counts, stating the denominator in benchmark reports) is not implemented; the counters remain mutation-success estimates. Minor doc drift: `mongodb-cost-ledger.ts:21` cites `docs/cost-model.md`, actual file is `docs/platform/cost-model.md`.
