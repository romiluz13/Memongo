## Notes

- All seven findings reproduce verbatim at HEAD; none of the landed remediation workstreams (WS-11 search admission, WS-12 degradation, WS-13 KB cross-tenant, WS-14 orphans, WS-15 relation locator/bitemporal chunks, WS-16 retrieval, WS-18 release, WS-19 provenance labels, D2/D4) touched these surfaces.
- **API-01**: the defect is a two-layer skip — the API boundary manufactures NaN and lets it through, and both engines define NaN as "not enforceable" and then CAS on the current revision read in the same call, so a stale caller silently overwrites. Remedy per audit: `Number.isInteger && >= 1` at the boundary plus engine defense-in-depth.
- **API-03**: bound unchanged — requires malformed scoped-key configuration plus startup-log access; not a remote read.
- **API-04**: helper misclassification is confirmed in current code; end-to-end exploitability remains conditional on resolver/fetch behavior as the audit stated (bracketed-literal direct exploit not established).
- **API-05**: `apps/api/src/contract-conformance.test.ts` still checks registered names and table/spec agreement only, so omissions duplicated across both manual descriptions remain undetectable by the suite.
