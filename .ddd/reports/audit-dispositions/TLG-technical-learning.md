## Notes on PARTIAL / ambiguous cases

- **TLG-03 (PARTIAL).** The audit's initialization-race sub-claim is substantially fixed: the structured-memory initialization path is now an upsert with `$setOnInsert`, so concurrent first writes converge instead of racing insert-then-read. The revision-contract sub-claims persist: the absence branch writes a revision without an `expectedRevision` guard, the history snapshot is inserted before the compare-and-swap (orphan revision on CAS failure), and duplicate-key on the snapshot path is swallowed when the caller supplied the session. Classified PARTIAL rather than OPEN because the primary concurrency defect the audit led with is materially repaired.
- **TLG-06 (PARTIAL).** The audit asked for uniform bounds on provenance/history arrays. Three of the five cited growth paths are now capped (entities via C-028 pipeline `$slice`, relations at 200, structured merges). Procedures remain unbounded in both directions the audit named: `mergeSourceEventIds` grows without bound and each procedure revision copies the entire array, compounding storage per revision. Structured initial (non-merge) inputs are also uncapped. Net: boundedness is no longer absent, but it is not uniform.
- **TLG-11 (PARTIAL).** The routing defect — the finding's core — is untouched: all geographic (`eu-`/`us-`-style) Voyage keys still resolve to the default endpoint, so region-pinned keys silently hit the wrong deployment. The only improvement is on the secondary validation axis (score clamping in result processing); the audit's other validation asks (integer indices, uniqueness, cardinality vs input) are unmet. PARTIAL is generous and rests entirely on the validation improvement, not the routing fix.

No STATIC_UNVERIFIABLE classifications: every finding was decidable from current source, with driver behavior confirmed against installed `node_modules/mongodb/src/bulk/common.ts` (driver 7.5.0), exactly as the audit prescribed.
