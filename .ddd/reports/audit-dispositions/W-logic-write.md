## Notes on PARTIAL / ambiguous cases

- **W08** — The audit's single-write rejection case was fixed only for the *non-throwing* `released === false` path (P0.1). Every *thrown* post-commit error (chunk projection, job release, batch marker update, non-bulk batch job insert) still rejects an already-durable write exactly as the audit described. Repair markers mitigate convergence, not the acknowledgment contract.
- **W15** — The hash-not-advanced fix covers partial chunk-write failure on the non-transactional path. It does not cover process death after the independently committed delete, nor a thrown error on the transactional path: in both, stored hash still equals content hash and the next non-forced sync skips the file with chunks missing.
- **W18** — The new `stillOwned` revalidation prevents *executing side effects* under a dead lease, but does not move the heartbeat start earlier or bound reclaim loops for lease-expired `running` jobs, so the audit's stated consequence (repeated prefetch payment + ownership loss) still occurs.
- **W19** — WS-15 threaded the fence into typed-relation writes only. The core architecture gap (observation-based fence, no write-side token predicates on entity/structured/procedure mutations) is unchanged.
- **W02** — First-attempt receipt integrity was hardened (phase-1 failure now forces "partial"), but that was never the defect; the retry-after-parent-deletion false-complete path is byte-for-byte the audit's scenario.
- No finding required STATIC_UNVERIFIABLE or SUPERSEDED: every cited construct was located and inspected at HEAD; none of the W-findings' code surfaces were redesigned away.
