## Notes on PARTIAL and ambiguous cases

- **B01 (PARTIAL).** The post-audit rework (ab68243d4e) genuinely repairs the gold-label side: official expected turn IDs are restricted to user `has_answer` turns, sessions without a user answer target are excluded (the `noans` equivalent for the gold set), abstention questions are ineligible, and the flattened per-label projection is deflate-only for duplicates (nDCG can no longer exceed 1). What remains from the finding: (a) on the candidate side every memory sourced from any turn of an answer session — including assistant and non-answer user turns — still resolves to that session ID and awards an official session hit (`resolveBenchmarkResultSessionIds`), so the audit's repro (unrelated turn from answer session => session RecallAny@1 = 1) still holds at session level; (b) the cutoff is still a fixed k flattened slots (`idsAtK` slices then dedups), not the upstream expansion until k distinct projected session labels. The gate now also asserts `comparability === "canonical"`, but that label is self-declared (`mongodb-benchmark-runner.ts:1581`), not evidence of upstream equivalence.
- **B02 (PARTIAL).** The finding's subject is LoCoMo. The remedy was implemented generically (pass-0 context harvest, model binding, cost accounting, unavailable-never-zero envelope) but scoped to `datasetKind === "longmemeval"` only; the LoCoMo canonical path still produces no QA envelope and its contract still requires `minAnswerAccuracy: 0.8`, so the LoCoMo answer gate continues to fail closed exactly as the audit described. Note the audit also warned a custom LLM binary judge is not the official LoCoMo F1 evaluator — the new harness is an LLM judge, so even once wired to LoCoMo the comparison-metric decision remains open.
- **B07 (PARTIAL).** The configuration snapshot (input to `configurationHash`) now covers reranker, cache, graph, episodes, extraction, budget, and many env toggles, materially narrowing the silent-mix surface. The two core defects persist: resume is not bound to any source-commit/build/evaluator identity, and completed-scenario metric payloads (`executionsByPass`, expected-label maps, accounting internals) pass only structural checks — a tampered or stale checkpoint's scores are still trusted.
- **B12 (PARTIAL).** Speaker names now survive in turn metadata (`locomoSpeaker`), which partially addresses "include speaker identity independently of human/assistant trust". The trust-relevant defect — mapping one human speaker to the `assistant` role — and the silent loss of non-string gold answers both remain.
- **B19 (PARTIAL).** WS-18 bound publishing to the real-MongoDB tier-A e2e job and added a post-publish registry smoke with pinned versions — the largest gap in the finding. Still missing per the finding: nightly/benchmark-publicationDecision/proof-pack/real-agent acceptance binding, a tag-to-manifest version comparison, and resumable/atomic multi-package release state (the all-versions-unpublished preflight still turns a partial publish into a retry blocker).
- **B08 (OPEN despite list growth).** The cleanup suffix list added three collections, but every collection the audit named as omitted (query_cache, access_events, memory_telemetry, memory_quarantine, files, meta) is still omitted, and rejected deletes are still log-only; classified OPEN since the cited defects all persist.
- **STATIC_UNVERIFIABLE:** none — all 26 findings were classifiable from static code at HEAD. (B05/B06 live-run behavior, e.g. actual probe counts, was not executed, but the cited code defects are statically present/absent as recorded.)
