But the finding's subject — the gauge/drain definitions and one-shot sampling — is byte-for-byte unchanged, so the finding itself stays OPEN. The audit's suggested distinct pending/staged/retryable/inflight/dead-letter/unknown gauges are not implemented.

No availability/completeness signal was added; a failed aggregation is still indistinguishable from zero spend.
- **DW03**: Pure test-fidelity gap; no fixture change since the freeze. The dedicated helper tests (`mongodb-manager-write-queue.test.ts`) still initialize depth correctly, so helper-level coverage remains valid; manager-level saturation is still unexercised through the fakes.
- **DW04**: No integration work landed: the engine throws the typed error, the bridge passes it through untyped, and the API error mapper's closed 503 set (`errors.ts:38-42`) does not include it. The "state the precise bound" half of the remedy is partially met by the expanded header comment (`mongodb-manager-write.ts:50-60` documents the fast-fail policy), but no event/byte budget or public overload mapping exists.
