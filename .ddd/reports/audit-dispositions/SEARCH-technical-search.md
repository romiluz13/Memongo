## Notes on PARTIAL / ambiguous cases

- **SEARCH-03 (PARTIAL).** The audit's core claim — declaring `quantization: "none"` does not yield unquantized storage — is intact: the builder omits the field for `"none"` and the server default applies. What changed is honesty of the loop: the configured value is now shipped in the definition, a server rejection is recorded in the capability registry, and the retry uses the server default (P3.4 probe-adopt). Benchmark identity acknowledges the Atlas scalar default. The declared-vs-actual reproducibility gap the audit measured is still present, so PARTIAL rather than FIXED.
- **SEARCH-04 (SUPERSEDED).** Classified SUPERSEDED rather than FIXED because the underlying fact (MongoDB automatic embeddings are Preview) cannot change in this repo; what changed is the project's posture toward it. WS-04/ADR-0006 converted an implicit dependency into an explicit supported-target contract with loud failure outside it, which is precisely the audit's stated remedy. If the program expects only code-level fixes to count as FIXED, this should be read as "remedied by contract".
- **SEARCH-12 (PARTIAL).** Two of the audit's four sub-claims are fixed (time-range/fusion/reranker parameterization now in the cache key; cross-parameterization serves rejected via `keySuffix`). Two persist verbatim (no source-expiry coupling on either read or write; no revalidation of source permissions/expiry on hit). The audit's own severity note — that top1-then-reject is a false-miss/performance issue rather than cross-policy disclosure — is honored; the remaining exposure is staleness beyond source expiry, matching the audit's "cap entry life by source deadlines" remedy.
