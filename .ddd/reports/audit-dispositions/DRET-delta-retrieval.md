## Notes

- **DRET-01**: the plain `search()` return type is still `Promise<MemorySearchResult[]>`, so the array itself carries no marker — but WS-12 moved the typed outcome to the `onDegradation` sink (`kind: "throttled"`, `retryAfterMs`), which rides through manager → bridge → API. All three audit sub-claims (bare empty array, executor dropping `throttled`, detailed fallback bypassing denial) are repaired. Classified FIXED on that basis.
- **DRET-03**: the only remediation present is documentation — the admission header now explicitly describes the bucket's process-local, read-path-only scope (`mongodb-search-admission.ts:24-44`). The cache probe still embeds outside admission and no provider-quota/tenant-fairness layer exists. The defect as described stands.
- **DRET-04**: WS-16 makes the rerank stage consume only the remaining tail budget, so probe+aggregate+rerank within one `searchV2` call is partially composed. The 13.5 s figure is still a sum of constants in a test with no timer; retry loops (`mongodb-search.ts` warmup retries) and multi-pass detailed execution still have no shared request deadline.
- **DRET-05/06**: both findings offered "label it best-effort OR make it durable" as remedy. The labeling half landed (WS-10 docs); the observability-truth gaps (estimate vs confirmed, failure-indistinguishable-from-empty, no rerank channel, no provider/model provenance) remain.
- **DRET-07**: the `throttled` marker enables the separation the audit asked for, but no aggregation actually uses it yet, so heavy denial still depresses search percentiles in `getLatencyStats`.
- **DRET-08**: all three sub-defects persist verbatim. Low severity; the fixture mismatch is compile-time-only since test files are excluded from `tsconfig`.
