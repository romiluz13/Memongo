Memongo is **MongoDB-native long-term memory for AI agents**.

It gives apps and agents a durable memory layer backed by MongoDB collections,
MongoDB Search, Vector Search, and hybrid retrieval. The public repo focuses on
the supported product path: API server, MCP server, TypeScript client, AI SDK
tools, web console, Docker setup, and release checks.

## Start with one loop

The fastest way to understand Memongo is:

1. Start MongoDB.
2. Start the Memongo API.
3. Add one memory.
4. Search for it.

## What it stores

| Memory type | Use case |
|---|---|
| Conversation events | Long-running chat and agent history |
| Structured facts | Preferences, profile details, current state |
| Procedures | Workflows, playbooks, and instructions |
| Knowledge base chunks | Documents and reference material |
| Episodes and graph links | Higher-level context and relationships |

## Runtime shape

```text
App / Agent / MCP client
  -> Memongo API or TypeScript client
  -> Memory bridge
  -> MongoDB memory engine
  -> MongoDB
```

Memongo keeps the integration surface small while the engine handles indexing,
retrieval, telemetry, graph relationships, and memory lifecycle behavior.

## Why MongoDB

Memongo uses MongoDB as the memory substrate instead of bolting together a
separate vector database, relational store, and event log. That keeps source
documents, vector search, lexical search, metadata, provenance, and operational
queries in one place.

## Evaluation posture

Benchmark evidence is scoped by lane. Memongo currently publishes selected
MemPalace retrieval-lane evidence only. Broader ecosystem and judged-answer
benchmarks remain under audit, and no Mem0 LongMemEval win is claimed.
