# Memongo 2.2.2

This patch preserves repeated bare possessive user facts when extraction differs
only by one terminal sentence period. The eight public packages use version 2.2.2.

For example, a repeated user statement `My pickup label is SAMPLE-123.` can support
an extracted `The user's pickup label is SAMPLE-123` without changing the stored
candidate value. The same narrow equivalence works in the reverse direction.
Contextual claims retain the existing behavior; unrelated bare facts,
deterministic extraction and existing durable-memory promotion are unchanged.

Both the current event and its supporting events must contain the full claim in
the same agent/scope and remain eligible under lifecycle rules. At least one
canonical event must be user-authored. Before the write, the fence rechecks exact
raw event roles, bodies and timestamps. Quoted or named speakers, extended or
incorrect values, internal punctuation differences and assistant-only evidence
do not supply that witness. Previously accepted embedded literals no longer count
as support for bare possessive claims.

## Validation scope

Offline regressions exercise manager event writes, job extraction and fenced
promotion with an in-memory database adapter and mocked provider responses.
These checks do not establish live MongoDB regex behavior, server concurrency,
benchmark quality, provider behavior or API deployment. Release gates must pass
against the final revision; package and image publication do not establish an
operational API host.
