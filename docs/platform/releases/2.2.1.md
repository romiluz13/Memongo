# Memongo 2.2.1

This patch ships accepted memory persistence, reranking, lifecycle and benchmark
readiness repairs. The eight public packages use the coordinated version 2.2.1.

## Changes

- Add opt-in derived-memory diagnostics for extraction and promotion outcomes.
- Upgrade the MongoDB Node.js driver dependency to ^7.7.0 and isolate benchmark
  scenarios through the supported factory with an empty workspace. Close each
  scenario before measuring storage through its host client.
- Default HTTP reranking to rerank-3 and bound rerank windows consistently.
- Accept one optional terminal sentence period when matching contextual LLM
  full claims to user evidence. Preserve the original candidate value and
  existing user, scope and lifecycle fences.
- Await evicted managers' pending writes before closing shared MongoDB clients.
- Keep required benchmark text/vector index readiness enabled for invalid or
  zero timeout input in strict mode. Non-strict explicit zero still opts out.

## Benchmark checkpoint compatibility

Run configuration now records effective numeric text and vector readiness
settle timeouts using the execution resolver. This changes configuration hashes,
including when normalized raw settings look alike: EVENT=17 with VECTOR blank
uses 300000 ms, while VECTOR unset uses 17 ms. Existing checkpoint hashes are
incompatible and must not be reused. Start fresh runs and paired controls from
this revision when comparing results. VECTOR ?? EVENT precedence is unchanged.

## Validation scope

Offline regressions cover the repaired persistence, rerank, shutdown and required
readiness paths. Release gates must run against the final revision. These checks
do not establish full benchmark quality, deployment availability, server-side
cleanup success or whole-platform production readiness. Atlas/provider workloads
are separate qualifications; this patch does not claim they were rerun.
