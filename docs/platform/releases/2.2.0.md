# Memongo 2.2.0 reliability release

This release incorporates 140 independently reviewed bounded repairs across the
memory engine, HTTP API, client, MCP server, and agent middleware. This count
tracks accepted changes, not distinct defects or measured accuracy improvements.
MongoDB remains the storage backend. Public APIs evolve through additive owner
coordinates, bounded requests, and more specific conflict responses.

## Observable changes

- Lifecycle admission and epoch fences prevent stale work from writing through
  selected erasure and replacement paths. Background jobs retain their original
  admission across scoped reads, transactions, retries, and diagnostics.
- HTTP, MCP, SDK, and middleware propagate and validate supported owner coordinates.
  Scoped authority checks cover the repaired context and lifecycle paths.
- Query, diagnostic, and pattern processing is bounded. Nested database and
  provider errors are redacted at repaired diagnostic boundaries.
- Quarantine promotion preserves resolved identity and session coordinates.
  Ambiguous legacy identities fail with a conflict before promotion claims work.
- The MCP executable starts through npm-generated symlinks.
- Automatic paid wiki generation and scheduled provider tests are suspended.
  Their manual workflows remain available. This release starts no paid benchmark.

## Verification scope

Release validation uses Node 24.19.0, Bun 1.4.2, MongoDB Node.js driver 7.6.0,
and an isolated MongoDB 8.2.6 replica set. Exact command results are retained
in the release receipt and GitHub Actions for the tagged revision. A passing
unit test is not evidence of Atlas retrieval or model quality.

## Known limits

The original next-generation roadmap remains broader than this release.
Complete writer-inventory coverage, cross-process CAS, load, failover,
retention/grant policy, and deferred history behavior are not certified here.
Owner decisions concerning rationale and self-edit remain unresolved.
Legacy quarantine configuration other than restored session coordinates is
not fully retained; concurrent deduplication behavior is not repaired.

Atlas search/vector, automated embeddings, and provider/model lanes are not
re-verified for this release. MongoDB labels Automated Embedding Preview and
explicitly says not to use it in production. See the
[official MongoDB warning](https://www.mongodb.com/docs/vector-search/crud-embeddings/automated-embedding/).
A deployment relying on that feature must retain its preview qualification.

This release does not establish the full [production-ready checklist](../PRODUCTION-READY.md),
a hosting SLA, or a win against competing memory systems. The running B2
benchmark uses its pinned earlier revision and is not evidence for this release.
No "best in the world" claim is supported.

## Deployment artifacts

Coordinated public packages use version 2.2.0. The tagged release publishes
npm packages and the GHCR container through the repository's gated workflows.
The existing Cloudflare `memongo` web worker is deployed separately after those
gates pass. Publishing an API container does not deploy a hosted API service;
no remote API deployment target is configured in the repository.
