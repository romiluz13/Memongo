# Memongo v1.1.0 Release Candidate

Status: release candidate in progress
Date: 2026-04-11
Active plan: `docs/plans/2026-04-10-benchmark-first-harmony-execution-plan.md`
Architecture constitution: `docs/plans/2026-04-10-harmony-memory-roadmap.md`

## Why `v1.1.0`

- The repository already has a product tag at `v1.0.0` from 2026-03-30.
- As of 2026-04-11, the npm registry has no published `@memongo/*` packages.
- The current release train is additive relative to `v1.0.0`: new recall,
  lifecycle, benchmark, provenance, and release-proof capabilities without a
  deliberate breaking contract reset.
- The coordinated publishable package set is therefore normalized to `1.1.0`
  instead of reusing `1.0.0` or leaving the scope split across `1.0.0` and
  `0.1.0`.

## Release scope

This release candidate covers the supported Memongo product core:

- `apps/api`
- `apps/mcp`
- `apps/web`
- `packages/memory-engine`
- `packages/memory-bridge`
- `packages/memongo-memory`
- `packages/client`
- `packages/tools`

Published npm package set:

- `@memongo/lib@1.1.0`
- `@memongo/memory-engine@1.1.0`
- `@memongo/memory-bridge@1.1.0`
- `@memongo/memory@1.1.0`
- `@memongo/client@1.1.0`
- `@memongo/tools@1.1.0`

## What shipped in this release train

- First-class conversation recall across engine, bridge, API, MCP, client, and tools
- Benchmark report envelopes with build identity, corpus identity, official metrics, and release gates
- Lifecycle get/update/delete/history surfaces with invalidate-with-history semantics
- Canonical conversation import and benchmark dataset ingest hardening
- Temporal truth convergence on touched structured, graph, and recall-sensitive paths
- Semantic MCP aliases over the same runtime truth
- Public feedback, provenance, mutation, and procedure-outcome surfaces
- Release-proof harnesses for proof-pack, memory-eval, agent-smoke, and capability-stress
