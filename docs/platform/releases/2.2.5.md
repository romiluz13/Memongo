# Memongo 2.2.5

This patch makes malformed generic benchmark input visible instead of silently
dropped. The generic JSON and JSONL benchmark loader returns a typed rejection
for each malformed record, with its line (JSONL only), conversation index, turn
index (turn-level only) and reason. Reasons are `turn-not-object`,
`invalid-role`, `empty-body`, `conversation-not-object`, `turns-not-array` and
`no-valid-turns`, matching the conversation importer.

## Behavior changes

- `failedLines` counts only JSONL lines that are not valid JSON. A line that
  parses but has an invalid shape is reported in `rejectedConversations` or
  `rejectedTurns` instead, so `failedLines` can be lower than in 2.2.4 for the
  same input. Read all three counters together.
- Benchmark ingest results, run-level results and checkpoints record
  `rejectedTurns` and `rejectedConversations` beside `failedLines`. QA summaries
  and runner warnings name rejected conversations and turns.
- Publication benchmark runs refuse datasets with any failed line or rejection.
  Resume refuses a checkpoint whose rejection counts differ from the loaded
  dataset. Comparison eligibility requires both counts to be recorded as zero;
  checkpoints without them are ineligible.
- When every generic record is rejected, the loader error reports the counts and
  carries the rejections. A legacy query/expected dataset still falls back to
  the legacy relevance benchmark.

## API and client

The OpenAPI conversation-import response now documents `rejectedTurns`,
`rejectedConversations` and `rejections`, the diagnostics the engine already
returns. `@memongo/client` adds them as optional fields on
`MemongoConversationImportResponse` and exports
`MemongoConversationImportRejection`. The relevance benchmark result type
declares the optional rejection counts on `ingest`.

## Validation scope

Focused offline regressions cover rejection coordinates for JSON and JSONL
input, receipt and checkpoint counts, publication, resume and comparison
refusals, the legacy fallback, the OpenAPI schema and the result type. Pinned
LoCoMo, a pinned 50-question LongMemEval sample and valid generic JSON/JSONL
normalize identically to 2.2.4. The full LongMemEval set was not run.

The LongMemEval and LoCoMo adapters still drop malformed rows without rejection
counts. An import in which every record is rejected still returns HTTP 500. These
checks do not establish retrieval quality, benchmark gains, live MongoDB
behavior or provider performance.

Release CI, package installation and publication, and deployment verification are
separate gates. Package or API image publication does not establish a hosted API
service. These notes do not assert that the Cloudflare web worker or GHCR API
image has been deployed at this version.
