# Memongo 2.3.0

This minor release adds `POST /v1/events/get`, a governed read of one
conversation event by id. The body carries `eventId` (a non-empty string of at
most 256 characters without control characters) and the usual identity fields:
`agentId`, `scope`, `scopeRef` and `sessionId`. Identity resolves by the same
rule as other reads: an explicit scope wins, a session coordinate implies
session scope, and otherwise the configured default scope applies.

A match returns `{ eventId, role, body, timestamp, scope, scopeRef }` plus
`validAt` when the event carries one. An unknown id, an event owned by another
agent, an event under another scope or scopeRef, and an expired event all
return the same 404 `EVENT_NOT_FOUND` body, so the response does not reveal
that an id exists elsewhere. The lookup uses the existing unique `eventId`
index; no schema or index migration is needed. No other route changes
behavior. The OpenAPI contract version moves from 2.2.3 to 2.3.0.

## Validation scope

Offline tests cover the engine lookup against the in-memory storage adapter
(own, other agent, other scope, other scopeRef, expired, session coordinate and
default scope) and the HTTP route with the bridge mocked (validation, identity
forwarding, identical 404 bodies and failure mapping). They do not exercise a
live MongoDB deployment or an operational API host.
