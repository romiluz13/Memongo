# Memongo 2.2.4

This patch fixes conversation import and benchmark reporting integrity. Large
collections of rejected turns retain their individual diagnostics without
exceeding JavaScript's function argument limit. Benchmark runs with failed
lines or turns retain diagnostic results but withhold complete headline scores,
including when failures are restored from a checkpoint. Malformed or inconsistent
checkpoint failure counters are rejected.

## Benchmark timestamp compatibility

The benchmark timestamp treatment is now
`benchmark-timestamp-utc-fields-literal12h-v1`, with run configuration coverage
`b02-keyed-v3`. Supported ISO, LongMemEval and LoCoMo timestamp forms are parsed
explicitly; invalid calendar fields fail preflight before ingestion. Benchmark
replay, direct ingestion, session evidence and question cutoffs use the same UTC
interpretation. Raw source labels remain available for prompts and diagnostics.

LoCoMo twelve-hour labels follow the released text: `12 am` means midnight and
`12 pm` means noon. A generator's noon-labeling behavior does not establish that
every released timestamp was produced by that generator revision. This policy
is explicit and versioned so a future evidence-backed correction requires a new
treatment identity.

These changes invalidate earlier benchmark comparison baselines and checkpoint
identities. Start fresh runs and paired controls; do not resume old campaigns or
compare results across parser treatments as if their inputs were equivalent.

## Validation scope

Focused offline regressions cover ingestion rejection counts, failed-ingestion
QA reporting, timestamp grammar and calendar validation, UTC/time-zone parity,
preflight write prevention, and checkpoint/comparison identity rejection. These
checks do not establish retrieval quality, benchmark gains, live MongoDB behavior
or provider performance. The broader benchmark input-normalization contract
remains incomplete; this patch does not claim that every malformed conversation
shape has a typed rejection result.

Release CI, package installation and publication, and deployment verification are
separate gates. Package or API image publication does not establish a hosted API
service. The repository configures the existing Cloudflare web worker and GHCR
API image; these notes do not assert that either has been deployed at this version.
